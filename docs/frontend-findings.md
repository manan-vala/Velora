# Frontend Findings

## Medium severity

### F1. Duplicated desktop and mobile stacks
- Two Zustand stores (`store/useAppStore.ts`, `store/useMobileStore.ts`), two optimization hooks (`hooks/useOptimization.ts`, `hooks/useMobileOptimization.ts`), two map implementations (`components/map/MapInterface.tsx`, `components/mobile/visualiser.tsx`), two map theme files, duplicated FAQ / feature cards.
- They already drift: desktop turns on the routes layer when a job *starts* (`useOptimization.ts:39`), mobile when it *completes* (`useMobileOptimization.ts:49`).
- **Fix:** one store and one hook shared by both platforms; keep only layout components separate.

### F2. Blank first paint on every page
- `app/providers/DeviceRoutingProvider.tsx` wraps the whole app in `app/layout.tsx` and returns `null` until its effect runs. With `output: "export"` every exported page ships empty HTML — slow first paint, nothing for crawlers.
- **Fix:** only gate the `/` ↔ `/mobile` redirect, render children immediately, or use responsive layouts instead of redirects.

### F3. Polling has no timeout or failure handling
- `refetchInterval` polls every 15 s until `completed`/`failed`, with no max attempts or elapsed-time limit. Combined with backend finding B8 (unknown IDs report `processing`), a job can spin forever.
- Network errors leave `optimizationStatus` at `"processing"`.
- The task ID lives only in memory — reloading the page loses a running job.
- **Fix:** cap polling time, surface errors, persist `taskId` (e.g. `sessionStorage`) and resume polling on load.

### F4. Type contract does not match the backend
- `OptimizationStatusResponse.result` is typed `OptimizationResponse` (`types.ts:314`), but the backend returns an `OptimizationResult`; the mismatch is hidden with `as any` (`useOptimization.ts:122`).
- `Employee`/`Vehicle` include `[key: string]: ...` index signatures, which disable most type checking.
- The parser casts raw rows with `as Employee[]` — no validation before sending; the first validation happens server-side (422).
- **Fix:** generate types from the FastAPI OpenAPI schema, or validate with zod before submission.

### F5. Parser diverges from the backend parser
- Sheets matched by substring (`lib/excel-parser.ts:132-153`) vs exact names in pandas.
- Empty cells are skipped by `eachCell`, so keys go missing → Pydantic 422 with a raw message.
- Numeric ID cells become numbers → rejected by Pydantic `str` fields.
- See backend finding B5 for the root fix (parse once on the server).

### F6. Map rendering performance
- One office marker is rendered per employee (`MapInterface.tsx:523-537`, same in mobile), all at the same location.
- The simulation calls `setState` every 100 ms (`MapInterface.tsx:132-156`), re-rendering the full map component including every marker and InfoWindow.
- Polyline effect depends on `mapRef.current`, which is not a dependency; if results arrive before the map loads, routes are not drawn until another dependency changes.
- The TaxiMeter's "time" is animation wall-clock seconds, not route time; distance sums decoded polyline points, including the injected straight endpoint segments.
- **Fix:** deduplicate office markers, move the taxi marker into its own small component (or update an imperative `google.maps.Marker`), derive meter values from `route_sequence`.

## Low severity

- Mobile login/signup (`components/mobile/Auth/*.tsx`) only simulate success; they never call `/login` or `/register`.
- `console.log` of the full parsed payload and results in production (`lib/api.ts:20`, `36`, `50`; hooks).
- Default fallback center is hardcoded to Bangalore (`MapInterface.tsx:114`).
- `components/map/component-example.tsx` and `example.tsx` are scaffold leftovers.
- `app/layout.tsx` metadata description is still "Generated by create next app".
- Capacitor `appId` is `com.example.app`.
- ~21 MB of debug APKs committed under `frontend/apks/` — use GitHub Releases instead.
- `NEXT_PUBLIC_MAPS_API_KEY` is baked into the static bundle (expected), so it must be restricted by HTTP referrer / Android package in Google Cloud.
- Mix of `.jsx` and `.tsx` in `components/home/`.
- No frontend tests.
